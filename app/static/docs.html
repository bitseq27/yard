Pixel Sway — pixel-art animation editor

Turn a static pixel-art scene into a seamlessly looping animation and a game-ready sprite bundle. Everything runs locally: stdlib Python server + numpy/PIL engine, single-file browser editor, no external dependencies.

1 · Quick start

  1. Load a pixel-art PNG (drag & drop, or Load image). The editor detects the pixel grid and works at the art's native resolution.
  2. Auto-seg (A) proposes objects (plants, pots, water, lamps…) and regions (ground, walls). Accept the ones you want — each becomes an editable mask.
  3. Pick a mask and choose an anim type in the inspector (right panel); tune speed/amplitude, or apply a preset.
  4. Render in the timeline bar (bottom) — the frame strip previews the loop; the audit line must read stray 0.
  5. Export GIF (preview, ≤2 MB discipline) and/or Export bundle (game-ready zip, §7).
Loops are seamless by construction: every waveform completes an integer number of cycles in N frames, and the audit checks frame N−1 → 0 too.

2 · Masking tools

toolkeywhat it does
BrushBpaint/erase mask pixels at the native grid (nib size in the rail)
WandWflood-select by colour tolerance; adds to (or subtracts from) the mask
Auto-segAsegment + recognise the whole scene; presents an accept-list
Edge ops—grow/shrink/solid the selected mask (server-side morphology)

Masks are stored as row-run RLE in the project doc — tiny JSON, exact pixels. Objects animate; regions (kind=region) never animate but feed the walkmask in bundle exports. Hidden masks (eye off) are treated as background: they stay plate material and are inpainted away like the rest of the scene hole.

3 · Animation catalog

Seven types, all deterministic, all loop-seamless (plan §3). Ranges are (min, max, default, step); phase defaults to auto — derived from the object's position so crowds don't march in lockstep.

typeparamsgood for
swayspeed 1–3, amp 0.5–2, gust 0–0.3, phase foliage: the blob is split into leaf units (erode → cores → multi-source BFS), each unit articulated in 3 chunks with its own waveform + gust noise
bobspeed 1–3, amp 0–2, circ 0–1, phase floating/breathing objects; per-component offsets, circ bends the path circular
ripplespeed 1–3, wavelength 6–40, amp 0.5–2 water: horizontal run displacement, footprint clipped to the water silhouette
shimmerspeed 2–4, coverage 0–1 specular sparkle: bright/dark pixel selection waves over the object
flutterspeed 2–4, amp 1–2, phase fast small-amplitude bob for banners, tassels, small leaves
gustflickgusts 1–4, strength 1–2, travel 8–40 mostly-still object that flicks briefly when a gust passes (event-based, rest frames at t=0 and N−1 keep the seam clean)
static—no motion; sprite still exported (engine may bob it)

Params are clamped and whitelisted server-side; hostile values fall back to defaults (anim falls back to static). Params carry over across type switches when names match — intentional, so amp survives sway→bob→sway.

4 · Shadow sync

Toggle shadow per object (inspector). For movers (sway/bob/flutter/gustflick) the engine finds the cast shadow hugging the mask — dark pixels (val<0.32 and blue-ish or desaturated) within 2px of the object that no higher object claims — and rides them along with the piece they belong to. The shadow's original pixels are inpainted out of the plate, so the moving ring is the only shadow visible. Statics (pots, urns) keep their own shadows untouched. The first claimer in z order wins a shadow pixel; overlap is never double-painted.

5 · Timeline & exports

  • N frames (4–96, default 48), fps (2–30, default 12).
  • Render builds the frame strip; clicking a strip cell scrubs, P plays, ,/. step.
  • Export GIF: scale 1–4 (default 2), palette 8–256 colours (default 128). One shared palette + no dither = no inter-frame flicker and tiny LZW output. Target ≤2 MB for chat/discord; the server warns above 8 MB.
  • Export bundle: game-ready zip (§7), always native scale.

6 · Projects & presets

Every upload creates a project under app/projects/<pid>/ (doc.json + native/original PNG + masks/ + out/). The header carries ✎ rename, ⧉ duplicate, 🗑 delete; the projects… dropdown lists recents. Mask edits autosave (debounced).

Param presets: built-ins (gentle, windy, …) plus your own saved per anim type — stored in the browser's localStorage, applied to the selected object.

7 · Game bundle format

bundle.zip
├── plate.png        native art, objects removed + holes inpainted (RGB)
├── walkmask.png     white = walkable (derived: ground regions minus object footprints)
├── palette.png      the shared palette as a 1×N strip
├── scene.json       everything below, engine-neutral JSON
├── objects/<id>.png RGBA sprite sheets, grid cols=8, frames in loop order
├── atlas_0.png …    M5: the same sheets shelf-packed into square pages (pad 1px)
└── (region masks feed walkmask.png; regions are not objects)

scene.json: native_w/h, grid, fps, loop_frames; per object id, name, label, z, depth, anchor [x,y], bbox, sheet {file, frames, cols, cell_w, cell_h, loop}, atlas {page,x,y,w,h}, clips [{name, anim, params, frames, fps, loop}]. Sprite cells are the render's verbatim RGBA (edges cleaned: RGB zeroed under alpha 0), so plate + sheets recomposited at anchors == the render frames exactly — the importer can trust pixel parity.

Atlas sampling: a sheet lives at atlas {page,x,y,w,h} inside atlas_<page>.png; frame t is the cell at (x + (t % cols)·cell_w, y + ⌊t / cols⌋·cell_h). Objects too large for a page have no atlas key — fall back to their sheet.file. Target engine is a custom web JS engine: plain JSON + PNG is the final format.

9 · Engine rules

  1. Native grid only — all motion is integer pixel shifts of source pixels; no interpolation, no sub-pixel anything.
  2. Loop seam — integer cycles per loop; frame N−1 → 0 is audited like every other step.
  3. Every unit every frame — sway re-places all leaf units each frame (z-order stable, no popping).
  4. Plate = art minus objects — holes inpainted (horizontal run fill + inverse-distance blend under long runs); plate is pixel-exact outside masks.
  5. Audit — motion is only allowed inside per-object allowed zones (bbox + margin, shadow rings included); stray_max must be 0.
  6. Claim order — an object never owns pixels a higher object covers; shadow rings claim before lower masks.
  7. Determinism — same doc + masks ⇒ byte-identical renders (seeded per object id).
  8. Sprite parity — bundle sheets recomposite to the render frames exactly.

10 · Performance & concurrency

  • Budget: 48 frames @ 384×512 renders in <10 s worst case (measured ~1.1 s on the reference fern scene; a typical 1536×2048 courtyard with 56 objects renders in ~1.5 s).
  • Render cache: keyed by doc + mask mtimes + N/fps + engine version — identical repeat requests answer from memory (cached:true), and a server upgrade can never serve stale frames.
  • Concurrency guard: heavy endpoints (render/gif/bundle) take their project's lock first — a double-click or two tabs serialise, and the second request hits the cache — then one of 2 global work slots. When nothing frees up within 90 s the answer is 429 {error, retry:true} instead of an invisible queue. Auto-seg takes the project lock only.
  • Sprite build: pieces blit through cached flat-index tables per integer offset, and frames whose offset pattern repeats are memoised — a frame costs a handful of numpy assignments, not a python loop over runs.

12 · Troubleshooting

  • “stray N px” in the audit — something moves outside its allowed zone; usually a mask that clips a moving neighbour. Grow the mover's mask or shrink the neighbour's.
  • GIF too big — drop scale to 1, palette to 64, or N to 24–32.
  • Object reads as “not moving” — big rigid blob: switch to sway (leaf-unit split) or raise amp; shimmer needs coverage ≥0.3 to sparkle visibly.
  • Shadow looks wrong — shadow sync only claims dark pixels hugging the mask; if the cast shadow is far or light, mask it as its own static object.
  • 429 busy — another render/export for the same project is still running; retry in a few seconds.
  • Streaks inside big holes — the vertical-blend inpaint pass reduces hard row steps; for pathological masks, split the object into two masks.
